# Контракт JSON API v1

API расположен в `/api`, без завершающего `/`. Даты `YYYY-MM-DD`, время `HH:MM`, идентификаторы — целые числа. Время занятий относится к часовому поясу организации (по умолчанию Europe/Moscow). Сервер рассчитывает итоговое расписание; клиент его не объединяет самостоятельно.

## Общие правила

Ошибки: `{"error":{"code":"validation","message":"Описание"}}`. Коды HTTP: 200 — успех, 201 — создание, 400 — валидация, 401 — нужна сессия, 403 — права/CSRF, 404 — запись не найдена, 405 — метод, 429 — лимит, 500 — внутренняя ошибка без раскрытия деталей.

Списки: `{"results":[],"count":0,"page":1,"page_size":50}`. Параметры `page>=1`, `page_size=1..100`. Поиск `q` нечувствителен к регистру, поддерживает кириллицу и инициалы преподавателей.

Ограничение — 180 API-запросов в минуту с IP на процесс, ответ 429 с `Retry-After`. На многопроцессном сервере настройте общее ограничение на обратном прокси. Административные операции используют Django session cookie и CSRF: войдите в `/admin/login/`, передавайте cookie и `X-CSRFToken` из `csrftoken`. CSRF не отключается для JSON или multipart.

В явном тестовом режиме `DEPLOY_SCHEME=http`, `DEBUG=0` имена cookies — `schedule_sessionid` и `schedule_csrftoken`: токен из последней передаётся в тот же `X-CSRFToken`. Origin должен совпадать с внешним адресом, включая порт (например `http://185.171.83.215:5555`). Защита CSRF сохраняется, а HTTP не обеспечивает шифрование учётных данных.

## Публичные маршруты

| GET | Параметры / результат |
|---|---|
| `/api/meta` | `date`; текущее время, учебные годы/периоды, звонки выбранной даты, `week` выбранной даты и `current_week` сегодняшнего дня, время обновления, флаг сотрудника |
| `/api/bells` | `date, weekday=0..5` (необязательно, день в выбранной неделе); `date, weekday, slots, week, shortened_day` с учётом звонков по дням и сокращения на дату |
| `/api/subjects` | `group` обязателен; `date, period, q`; `group, period, version, subjects, teachers, subgroups`. У предмета: `id, name, short_name, teachers, weeks` (номера 1/2) |
| `/api/groups` | `q, course, specialty, building, year, archive=1` |
| `/api/teachers` | `q, archive=1` |
| `/api/rooms` | `q`; каталог помещений |
| `/api/groups/{id}/schedule` | `date, view=day\|week` |
| `/api/teachers/{id}/schedule` | `date, view=day\|week` |
| `/api/rooms/{id}/schedule` | `date, view=day\|week` |
| `/api/rooms/availability` | `date, start, end, slot, building, floor, capacity, type, status, q, grid=1` |
| `/api/changes` | `date, group, teacher, building`; опубликованная история редакций на исходную дату |
| `/api/academic-years` | Учебные годы и статусы |

Дополнения для формата колледжа: XLSX `/api/admin/imports` может не содержать profile/period/start/end — используется профиль college и даты из файла. Для замены только одной группы в совместном занятии задаётся `target_group_id`; остальные участники сохраняются. Интерфейс загрузки и проверки изображений доступен в `/admin/schedule/imageimport/`. Персональные оригиналы выдаются через защищённый маршрут, не через публичный MEDIA_URL.

`date` по умолчанию сегодня. Неделя начинается с понедельника. Флаг `archive=1` включает архив; `year` выбирает членство группы в конкретном году. Без архивного режима показываются действующие группы выбранного или активного года.

`week` содержит `number` (1/2 или null вне настроенного года), `label`, `type` (`odd` = первая, `even` = вторая), даты `start/end`, `anchor_date`, `anchor_number`, `year_id`, `overridden`. Опорная дата — понедельник. Календарное исключение меняет номер только выбранного дня.

В каждом дне расписания также есть `week`, `empty_reason`, `next_date`, `windows`, `practice`, `shortened_day`. `has_data` относится к выбранной группе/преподавателю/кабинету. До начала действия файла возвращается объяснение и ближайшая действующая дата того же дня недели; занятия задним числом не создаются. `view=week` возвращает шесть дней, понедельник–субботу; запрос дня воскресенья — пустой массив `days`.

`windows` содержит только целые свободные пары между занятиями: `{slot,start,end}`. `free_intervals` сохраняет прежний смысл свободных временных интервалов, включая перемены. У группы на практике `lessons=[]`, а `practice` содержит `{id,title,start,end,organization,label}` с включительным окончанием; иначе null. Классные часы имеют `event_kind="class_hour"`, учебные занятия — `"lesson"`; классные часы исключены из `/api/subjects`. `/api/meta` дополнительно содержит `version`, `shortened_day`, `manage_bells`.

`shortened_day` — `{id,minutes,note,lesson_count,varied_duration,label}` или null. `minutes` — общая длительность по умолчанию; отдельные пары могут иметь собственную. `lesson_count` — количество действующих номерных звонков, `varied_duration` показывает различающиеся длительности, `label` содержит готовую краткую подпись. При сокращении дня до N пар занятия с номером выше N не выдаются, включая занятия со своим временем. Исключённая пара отсутствует в `slots` и сетке кабинетов, запрос её занятости через `slot` возвращает 400. Классный час с номером 0 не входит в лимит. Отключение правила возвращает обычное расписание. Перемены в `slots` уже учитывают индивидуальные настройки.

`GET /api/admin/image-candidates?group=…&date=…&subject=…&teacher=…&room=…&slot=…` требует сотрудника с доступом к группе. Возвращает словарь `/api/subjects` и `suggestions: {subject_id,teacher_id,room_id,subgroup_id,inferred,confidence,inferences}`. Близкий вариант подбирается в словаре группы; предположения отмечены `inferred`, `inferences` объясняет выбор, `confidence` — эвристическая оценка 0–100, не статистическая вероятность. При отсутствии данных идентификатор может быть null. Эндпоинт ничего не публикует.

Изображения используют `target_group_id` и `target_subgroup_id`, чтобы менять только выбранных участников совместной пары. Остальные участники сохраняются; повторные редакции выбираются отдельно для каждой области изменения. Операционные HTML-формы звонков и практик доступны администратору в `/admin/bells/` и `/admin/practices/`, требуют сессии и CSRF.

### Ответ расписания

```json
{
  "id": 1,
  "name": "ИС-1-23",
  "kind": "groups",
  "days": [{
    "date": "2026-10-19",
    "has_data": true,
    "free_intervals": [{"start":"10:00","end":"11:40"}],
    "lessons": [{
      "id": 1,
      "date": "2026-10-19",
      "slot": 1,
      "start": "08:30",
      "end": "10:00",
      "subject_id": 1,
      "subject": "Базы данных",
      "teacher_id": 1,
      "teacher": "Пигачева Анна Сергеевна",
      "room_id": 2,
      "room": "102",
      "building_id": 1,
      "building": "Корпус 1",
      "groups": [{"id":1,"name":"ИС-1-23","subgroup_id":null,"subgroup":""}],
      "lesson_type": "Практика",
      "status": "changed",
      "change_id": 1,
      "reason": "Смена аудитории",
      "original": {},
      "current": false,
      "next": true
    }]
  }]
}
```

`original` содержит исходный DTO занятия либо null для дополнительного занятия. Статусы: `regular`, `changed`, `cancelled`, `moved`, `moved_out`, `added`, `reassigned`. Последний — отметка в расписании прежнего преподавателя/помещения. `moved_out` содержит `new_date`. У дополнительного занятия `id=null`, идентификатор записи — `change_id`. Отмены и отметки переноса не занимают ресурсы.

Свободные интервалы вычисляются в пределах минимального/максимального времени звонков. Для аудитории также вычитаются блокировки. `has_data=false` означает отсутствие опубликованной базовой версии; пустое расписание не считается гарантией доступности помещения.

### Занятость

По умолчанию проверяется текущая минута. `slot` заменяет start/end временем выбранной пары. Интервал `[start,end)` не пересекается с занятием, заканчивающимся точно в start. Интервал должен находиться внутри одних суток и иметь start < end.

Статусы `free`, `busy`, `unavailable`, `unknown`. Приоритет: недоступность/блокировка → занятость → свободно при наличии версии → нет данных. Ответ содержит параметры интервала и список помещений с `lessons`, `blocks`, `next`; при `grid=1` также `grid: [{slot,status}]`.

## Административные маршруты

Главная панель админки использует дополнительные защищённые session/CSRF-маршруты. Это JSON-ответы для загрузки без перезагрузки страницы; ошибка здесь имеет вид `{"error":"Описание"}`:

| Метод и путь | Назначение |
|---|---|
| POST `/admin/uploads/schedule/` | Multipart `file, course=1..4, publish=1` (либо пусто для предпросмотра). Проверяет курс по содержимому. Возвращает id, state=published/review, url, groups, rows, message и errors при необходимости |
| POST `/admin/uploads/changes/` | Multipart `image, target_date, layout=table/yellow`. Возвращает id, state=review, rows, url страницы проверки |
| GET `/admin/uploads/status/` | Актуальное состояние четырёх курсов, последние загрузки и количество изображений на проверке |

XLSX на этих маршрутах загружает администратор. Диспетчер может загружать изображения и видеть собственную историю. При конфликте автоматическая публикация не выполняется: возвращается state=review, опубликованное расписание сохраняется.

| Метод и путь | Назначение |
|---|---|
| POST `/api/admin/imports` | Multipart: `file, profile, period, start, end`; возвращает id, payload, errors |
| GET `/api/admin/imports/{id}` | Статус, сопоставленные строки и report с конфликтами/сравнением |
| POST `/api/admin/imports/{id}/confirm` | Атомарная публикация, `version_id` |
| POST `/api/admin/changes` | Создать черновик замены |
| PATCH `/api/admin/changes/{id}` | Изменить только черновик |
| POST `/api/admin/changes/{id}/preview` | Итоговые занятия и конфликты на дату назначения |
| POST `/api/admin/changes/{id}/publish` | Проверить все затронутые даты и опубликовать |
| POST `/api/admin/changes/{id}/withdraw` | Отозвать публикацию с проверкой отката |
| GET `/api/admin/conflicts?date=...` | Конфликты выбранной даты в доступных корпусах |
| POST `/api/admin/academic-years` | Администратор: `name, start_date, end_date` |
| GET `/api/admin/rollover?source=1&target=2` | Администратор: предпросмотр перевода |
| POST `/api/admin/rollover` | Администратор: JSON `source, target`; подтверждение перевода |

Для публикации версии, её отката, отмены предварительного импорта, активации года и CRUD справочников используйте HTML-панель `/admin/`.

### Поля черновика замены

`target_date, original_id, kind, new_date, time_slot_id, start_time, end_time, subject_id, teacher_id, room_id, group_id, subgroup_id, whole_group, reason`.

`kind`: `replace`, `cancel`, `move`, `add`. Для add обязательны группа/пара/дисциплина/преподаватель/аудитория и отсутствующий original_id. Для move обязательна new_date. Произвольные поля и ручное назначение автора/статуса запрещены.

```json
{"target_date":"2026-10-19","original_id":1,"kind":"replace","room_id":2,"reason":"Смена аудитории"}
```

После создания ответ `201 {"id":1,"status":"draft"}`. Черновик не влияет на публичные ответы. Публикация и откат регистрируются в журнале. Диспетчер видит собственные импорты и может менять данные только разрешённых корпусов; администратор имеет полный доступ.
