# Участие в разработке

1. Создайте отдельную ветку и установите зависимости из `requirements.txt`.
2. Опишите проблему и ожидаемое поведение в issue или pull request.
3. Бизнес-логику расписания меняйте в `schedule/services.py`, парсеры — в `schedule/importing.py`.
4. Добавляйте миграции при изменении моделей. Для сложных правил оставляйте короткий комментарий с причиной решения.
5. Выполните `python manage.py test`, `python manage.py check`, `python manage.py makemigrations --check --dry-run`, `node --check static/app.js`.
6. Не включайте в Git базы данных, файлы с реальными персональными данными, резервные копии и секреты.

Для нового формата Excel добавьте профиль и тест с небольшим искусственным файлом. Не пытайтесь автоматически угадывать неизвестного преподавателя или помещение.

Коммиты должны кратко описывать изменение. Лицензия проекта — MIT.
